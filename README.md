# 📋 WorkFlow Tracker — ระบบติดตามและบริหารจัดการสถานะงาน

**WorkFlow Tracker** เป็นระบบเว็บไซต์สำหรับจัดการงานภายในหน่วยงานและองค์กร สนับสนุนการเพิ่มงานส่วนบุคคล การมอบหมายงานจากผู้บังคับบัญชา การติดตามความคืบหน้า และการแจ้งเตือนกำหนดส่งงาน โดยพัฒนาด้วย **PHP, MariaDB, jQuery, AJAX, SweetAlert2 และ AOS** และออกแบบให้รองรับทั้งคอมพิวเตอร์ แท็บเล็ต และโทรศัพท์มือถือ

> 📌 **สถานะโครงการ:** รุ่นเริ่มต้นสำหรับการติดตั้งและทดสอบ (v1.0.0) ยังไม่ผ่านการรับรองการใช้งานในสภาพแวดล้อม Production ทุกกรณี

## ✨ คุณสมบัติของระบบ

- 🔐 **เข้าสู่ระบบ:** ใช้บัญชีจากตาราง `users` เดิม โดยตรวจสอบรหัสผ่านด้วย `password_verify()`
- 📊 **แดชบอร์ด:** สรุปงานทั้งหมด งานระหว่างดำเนินการ งานที่เสร็จสิ้น และงานเกินกำหนด
- 📝 **งานส่วนบุคคล:** ผู้ใช้สามารถสร้างและติดตามงานของตนเอง
- 👥 **การมอบหมายงาน:** ผู้มีสิทธิ์มอบหมายงานให้บุคลากรที่อยู่ภายใต้ขอบเขตสิทธิ์
- 🔄 **สถานะการดำเนินงาน:** `ได้รับมอบหมาย → กำลังทำ → ตรวจงาน → เสร็จสิ้น`
- 🗓️ **ปฏิทินงาน:** แสดงกำหนดส่งและรายการงานในแต่ละวัน
- 💬 **ความคิดเห็น:** บันทึกข้อความประสานงานในแต่ละรายการ
- 🔔 **การแจ้งเตือน:** รายการมอบหมายงาน ความคิดเห็น การเปลี่ยนสถานะ และงานใกล้ครบกำหนดหรือเกินกำหนด
- 📱 **Responsive Design:** รองรับการใช้งานบนหน้าจอหลากหลายขนาด

## 🛠️ เทคโนโลยีและข้อกำหนด

| ส่วนประกอบ | เทคโนโลยี |
| --- | --- |
| Backend | PHP 8.1 ขึ้นไป |
| Database | MariaDB / MySQL |
| Frontend | HTML, CSS, JavaScript, jQuery |
| การเรียกใช้งาน API | AJAX |
| การแจ้งเตือนในหน้าเว็บ | SweetAlert2 |
| Animation | AOS |
| Web Server | Apache พร้อม HTTPS และ `.htaccess` |

ฐานข้อมูลเดิมควรมีตาราง `users`, `works`, `projects`, `departments`, `activity_log` และ `status_history` รวมถึง PHP extension ที่จำเป็น ได้แก่ `pdo_mysql`, `mbstring`, `openssl` และ Session

## 🚀 ขั้นตอนการติดตั้ง

1. 💾 **สำรองฐานข้อมูลเดิม** ก่อนดำเนินการทุกครั้ง และไม่ควร Import SQL Dump เดิมซ้ำทับฐานข้อมูล Production
2. 🗄️ นำเข้า `database/migration.sql` ในฐานข้อมูลเดิมผ่าน phpMyAdmin เพื่อเพิ่มตาราง `task_notifications` และ `task_comments` โดยไม่ลบข้อมูลเดิม
3. 📁 อัปโหลดไฟล์ของโปรเจกต์ไปยัง Document Root ของเว็บไซต์หรือ Subdomain
4. ⚙️ คัดลอก `config/config.example.php` เป็น `config/config.php` และระบุการเชื่อมต่อฐานข้อมูลให้ตรงกับเซิร์ฟเวอร์
5. 🔒 เปิดใช้งาน HTTPS และตรวจสอบการป้องกันการเข้าถึงไดเรกทอรี `config`, `cron` และ `database`
6. 👤 เปิดหน้า `index.php` และเข้าสู่ระบบด้วยบัญชีผู้ใช้เดิม
7. ⏰ กำหนด Cron Job เพื่อสร้างรายการแจ้งเตือนในแต่ละวัน ตัวอย่างเวลา 08:00 น. ตามเวลาของเซิร์ฟเวอร์:

```cron
0 8 * * * /usr/bin/php /ABSOLUTE/PATH/cron/reminders.php
```

**หมายเหตุ:** โปรดตรวจสอบเส้นทาง PHP CLI และเขตเวลาของ Cron Job ให้ตรงกับสภาพแวดล้อมที่ติดตั้งจริง

## 📂 โครงสร้างไฟล์

```text
index.php                  หน้าเว็บหลัก
api/index.php              Backend API
assets/style.css           รูปแบบและการจัดวางหน้าเว็บ
assets/app.js              การทำงานของ jQuery และ AJAX
config/bootstrap.php       ฐานข้อมูลและ Session
config/config.example.php  ตัวอย่างการกำหนดค่า
database/migration.sql     SQL Migration สำหรับตารางใหม่
cron/reminders.php         งานตามกำหนดเวลาสำหรับการแจ้งเตือน
```

## 🔒 ข้อควรระวังด้านความปลอดภัย

- ⛔ **ห้ามเผยแพร่** `config/config.php`, รหัสผ่านจริง, Token หรือ SQL Dump ที่มีข้อมูลผู้ใช้
- 🛡️ ตรวจสอบสิทธิ์ของแต่ละบทบาทก่อนเปิดใช้งานจริง
- 🔑 ควรเพิ่มการจำกัดความถี่การเข้าสู่ระบบ (Rate Limiting) และตรวจสอบบันทึกเหตุการณ์
- 💾 ทดสอบการสำรองและกู้คืนฐานข้อมูลให้เรียบร้อยก่อนเปิด Production
- 📆 คอลัมน์ `works.due_date` เป็นชนิด `DATE` จึงแจ้งเตือนกำหนดส่งในระดับ **วัน** ไม่ใช่ชั่วโมงหรือนาที
- 🔔 SweetAlert2 แสดงการแจ้งเตือนขณะเปิดเว็บไซต์เท่านั้น หากต้องการแจ้งเตือนขณะปิดเว็บไซต์ ต้องเชื่อมต่อ Email, LINE Messaging API หรือ Web Push เพิ่มเติม
